# مدل امنیتی

## سطوح حمله و کنترل‌ها

| سطح | کنترل | پیاده‌سازی |
|---|---|---|
| endpoint عمومی /chat | توکن HMAC امضاشده در HTML + اعتبارسنجی Origin/Referer + rate limit per-IP | app/auth/security.py |
| پنل ادمین | هش SHA-256+salt، قفل ۵ تلاش/۵ دقیقه، نشست لغزان ۱ ساعته، مسیر مبهم /secure-panel-inotex | app/auth/security.py |
| prompt injection | بخش SECURITY ثابت در پرامپت (غیرقابل‌ویرایش مشتری) + محدودهٔ SCOPE + آزمون‌های خصمانه در مجموعهٔ طلایی (false-confident injection = 0) | app/services/openai.py، scripts/run_eval.py |
| نشت اسرار | کلیدها فقط در env/settings؛ گیت `secret_leaks=0` در ارزیابی؛ کلید هرگز به کلاینت نمی‌رود | run_eval.py گیت سخت |
| مسمومیت بازیابی | فقط منابع allowlist شدهٔ content/sources.json وارد دانش می‌شوند؛ انتشار با تأیید انسانی | ADR-006 |
| داده‌های شخصی | لاگ چت شامل متن پرسش/پاسخ است — سیاست نگه‌داری باید توسط بهره‌بردار تعیین شود (گپ شناخته‌شده) | backlog |
| خروج داده | هر مسیری که فایل یا خروجی انبوه تحویل می‌دهد یک سطر `applog.audit("data.export", ...)` با نام ادمین، IP، user agent و «چه چیزی» می‌نویسد | app/routers/admin.py (`audit_export`) |
| CORS | allow_credentials=false با «*»؛ ادمین same-origin | app/main.py |
| کوکی | COOKIE_SECURE=true در تولید (env) | app/config.py |

## قواعد سخت
- ربات هرگز پرامپت سیستم، env، یا محتوای تنظیمات را بازگو نمی‌کند (بخش SECURITY پرامپت + آزمون).
- هیچ credential ای در کد یا تم‌ها نیست؛ `ADMIN_CREDENTIALS.txt` فقط خروجی نصب اول است و باید حذف شود.
- اسکریپت‌های عملیاتی مخرب بدون پشتیبان اجرا نمی‌شوند (reset-content-to-defaults.py پشتیبان اجباری دارد).

## خروج داده و رد حسابرسی

یک فایل پشتیبان کل پایگاه داده است. بعد از نمایشگاه یعنی شمارهٔ خام هر شرکتی
که ثبت شده، `otp_challenges.destination` هر بازدیدکننده‌ای که تا امروز ثبت‌نام
کرده، و درهم‌سازی کد دسترسی هر ویزیتور. مسیر دانلود امن است (اسم فایل از
allowlist می‌گذرد و path traversal ممکن نیست)، ولی تا پیش از این هیچ ردی از
خودِ دانلود باقی نمی‌ماند.

قاعده حالا این است: هر مسیری که فایل، dump یا فهرست انبوهی از داده تحویل
می‌دهد، دقیقاً یک سطر `applog.audit("data.export", ...)` می‌نویسد. سطر شامل
actor (نام کاربری ادمین)، `ip` (از `client_ip`)، `user_agent`، `route` و
`target` است. `target` می‌گوید **چه چیزی** برداشته شد، نه محتوای آن. محتوای
خروجی هرگز داخل سطر نمی‌رود: `audit_logs` نگه‌داری جداگانه و طولانی‌تری دارد،
پس نقل محتوا یعنی ساختن نسخهٔ دوم و دیرپاترِ همان داده‌ای که این سطر قرار بود
مراقبش باشد.

تابع مشترک `audit_export` در `app/routers/admin.py` است و هرگز استثنا پرتاب
نمی‌کند. یک نوشتن حسابرسی که دانلود پشتیبان را بخواباند، از باگی که قرار بوده
درست کند بدتر است.

مسیرهایی که پوشش دارند در `tests/test_export_audit.py` فهرست شده‌اند و یک تست
با شمارش مسیرهای برنامه نگهبانی می‌کند: افزودن یک مسیر خروجی جدید بدون تصمیم
دربارهٔ سطر حسابرسی‌اش، تست را می‌شکند.

## نگه‌داری داده (تصمیم نگرفته)

این جدول‌ها امروز **هیچ پاک‌سازی زمان‌داری ندارند**. سطرها تا ابد می‌مانند و به
هر پشتیبانی که گرفته شود هم راه پیدا می‌کنند.

| جا | چه چیزی نگه داشته می‌شود | پاک‌سازی |
|---|---|---|
| `otp_challenges` | شمارهٔ خام (`destination`)، HMAC کد، نام، نام خانوادگی، شغل، سمت، علاقه‌مندی‌ها | ندارد |
| `company_leads` | شمارهٔ خام (`phone`)، `phone_hash`، نام و نام خانوادگی و سمت فرد، نام شرکت، `ip`، `user_agent` | ندارد |
| `edit_invites` / `lead_visitor_sessions` | درهم‌سازی توکن و کد، با `expires_at` | منقضی می‌شوند ولی سطرشان حذف نمی‌شود |
| `chat_logs` | متن پرسش و پاسخ بازدیدکننده | ندارد |

جذب سرنخ نمایشگاه صدها شمارهٔ خام از افراد **شناسایی‌شده در شرکت‌های نام‌برده**
اضافه می‌کند. این ترکیب (نام + سمت + شرکت + شمارهٔ تماس) از آنچه پیش از این در
سامانه بود حساس‌تر است.

دورهٔ نگه‌داری یک پرسش بی‌پاسخ از بهره‌بردار است، پس اینجا عمداً چیزی پیاده
نشده. آنچه ثبت می‌شود این است که تصمیم گرفته نشده، نه اینکه فراموش شده.
REL-009 در `docs/features/exhibition-lead-capture/SPEC.md` همین را می‌خواهد.
وقتی عدد مشخص شد، پاک‌سازی به همان الگوی `applog.purge_expired()` نوشته شود.
