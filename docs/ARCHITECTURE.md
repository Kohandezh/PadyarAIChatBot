# معماری پادیار — سامانه آواتار هوشمند و ویدئوچت‌بات سازمانی

سند مرجع معماری نرم‌افزار. مخاطب: توسعه‌دهنده‌ای که باید بدون دانش قبلی، سامانه را نگهداری یا توسعه دهد.

## ۱. نمای کلی

پادیار یک **CMS چت‌بات** است که به‌ازای هر مشتری جداگانه نصب می‌شود. مشتری محتوای خود
(پایگاه دانش پرسش‌وپاسخ دوزبانه، ویدیوها، برندینگ) را از پنل مدیریت وارد و مدیریت می‌کند.

```
┌────────────────────────────────────────────────────────────────┐
│  مرورگر بازدیدکننده                                            │
│  vanilla JS (core.js) + سیستم تم (Jinja2 partials + CSS)       │
│  آواتار Canvas 2D │ TTS مرورگر │ ضبط صدا (STT)                 │
└──────────────┬─────────────────────────────────────────────────┘
               │ HTTPS — توکن HMAC + بررسی Origin + محدودیت نرخ
┌──────────────▼─────────────────────────────────────────────────┐
│  FastAPI (app/)                                                │
│  routers → services → db  (لایه‌بندی یک‌طرفه)                  │
│  ماژول‌های هسته: chat, admin, search, dataset, theme           │
│  ماژول‌های اختیاری: voice, video, registration, leads و…       │
│  (با ENABLED_MODULES)؛ برندینگ ماژول نیست — کلیدهای            │
│  whitelabel_* در جدول settings است                             │
└──────┬───────────────────────────────┬─────────────────────────┘
       │                               │ فقط در Tier 2
┌──────▼──────────┐        ┌───────────▼───────────────────────┐
│  SQLite         │        │  هر سرویس سازگار با OpenAI        │
│  (۸ جدول)       │        │  Base URL + کلیدِ خودِ مشتری      │
└─────────────────┘        │  از پنل مدیریت قابل تنظیم است     │
                           └───────────────────────────────────┘
```

## ۲. خط لوله‌ی هوش دولایه

1. **لایه ۱ — پایگاه دانش محلی (بدون هیچ سرویس بیرونی):** نرمال‌سازی متن فارسی
   (`app/utils/normalizer.py`)، بسط مترادف‌ها، بردارسازی TF-IDF و شباهت کسینوسی +
   هم‌پوشانی Jaccard (`app/services/search.py`). اگر اطمینان ≥ آستانه (پیش‌فرض 0.20)،
   پاسخ از دیتاست برمی‌گردد — دوزبانه (`text` / `text_en` بر اساس `lang` درخواست).
2. **لایه ۲ — جایگزین هوش مصنوعی (اختیاری، قابل خاموش‌کردن):** دسته‌بندی نیت با مدل
   سبک؛ اگر خارج از دامنه بود، تولید پاسخ آزاد با مدل گفتگو. کل این لایه با کلید
   `openai_enabled` از پنل قابل غیرفعال‌شدن است و سامانه فقط با لایه ۱ کار می‌کند.

## ۳. انتزاع سرویس‌دهنده‌ی هوش مصنوعی

هیچ نام سرویس‌دهنده‌ای در کد مسیرهای اصلی سخت‌نویسی نشده است. `app/services/openai.py`:

- `provider_config()` → آدرس پایه و کلید، به ترتیب اولویت: تنظیمات پنل (جدول settings،
  کلیدهای `ai_api_base` / `ai_api_key`) ← متغیرهای محیطی (`OPENAI_API_BASE` /
  `OPENAI_API_KEY`).
- `model_for(task)` → نام مدل هر وظیفه (`chat` / `classify` / `stt`) از تنظیمات پنل با
  پیش‌فرض‌های امن.
- کلاینت دسته‌بندی کش می‌شود و با تغییر تنظیمات، بدون ری‌استارت بازسازی می‌شود.

نتیجه: مشتری می‌تواند سکوی ملی هوش مصنوعی، سرور درون‌سازمانی، یا هر endpoint سازگار با
OpenAI را با **کلید خودش** از پنل (تنظیمات ← هوش مصنوعی ← اتصال) وارد کند. کلید فقط در
پایگاه‌داده‌ی همان نصب نگهداری می‌شود و هرگز به کلاینت برنمی‌گردد (GET فقط `has_key`).

## ۴. سیستم ماژول

هر قابلیت یک ماژول است (`app/modules/registry.py`): ماژول‌های هسته (chat، admin،
search، dataset، theme) همیشه فعال‌اند؛ ماژول‌های اختیاری (voice، video،
registration، leads و…) با `ENABLED_MODULES` در زمان نصب تعیین می‌شوند و روترشان
اصلاً بارگذاری نمی‌شود. برندینگ (سفید‌برچسب) ماژول نیست: ۵ کلید `whitelabel_*`
در جدول `settings` است که از پنل (تنظیمات ← برندینگ) ویرایش می‌شود و در صفحهٔ چت،
نام پنل و صفحه‌های `/v` تزریق می‌شود. جدا از آن، سوییچ‌های زمان اجرا در پنل:
`openai_enabled`، `voice_enabled` (گفتار به متن)، `tts_enabled` (خواندن پاسخ‌ها) — هر سه
هم در UI اعمال می‌شوند و هم سمت سرور (fail-closed؛ مثلاً `/api/transcribe` با سوییچ
خاموش 403 برمی‌گرداند).

## ۵. سیستم تم

الگوی وردپرسی: `themes/base/partials/` پیش‌فرض‌ها را دارد؛ هر تم با فایل هم‌نام در
`partials/` خودش override می‌کند (وراثت child ← parent ← base از طریق FileSystemLoader).
جاوااسکریپت چت یک فایل مشترک است (`static/chat/core.js`) و تم‌ها فقط از طریق callback های
`ChatConfig` رفتار را سفارشی می‌کنند — هیچ fork ی از core.js وجود ندارد. CSS ساختاری در
`static/chat/base.css` و CSS بصری در `style.css` هر تم است. توکن‌های رنگ سه‌لایه‌اند
(primitive ← semantic ← component)؛ حالت روشن فقط لایه‌ی semantic را بازتعریف می‌کند و
تست خودکار، وجود hex خام بیرون از لایه‌ی primitive را رد می‌کند.

## ۶. مدل امنیتی

- **چت عمومی:** توکن HMAC امضاشده در HTML (TTL یک ساعت) + بررسی Origin/Referer در برابر
  allowlist + محدودیت نرخ per-IP (پیش‌فرض 20 درخواست / 60 ثانیه؛ env-پذیر برای نمایشگاه).
- **پنل مدیریت:** هش bcrypt (ارتقای خودکار از طرح قدیمی)، نشست کوکی با انقضای لغزان
  یک‌ساعته، قفل ۵ دقیقه‌ای بعد از ۵ تلاش ناموفق، تأیید رمز برای تغییر قواعد ایمنی.
- **پایگاه‌داده:** همه‌ی کوئری‌ها پارامتری؛ هیچ ورودی کاربر وارد SQL خام نمی‌شود.

## ۷. مدل داده (SQLite)

| جدول | نقش |
|---|---|
| `dataset` | پایگاه دانش دوزبانه: `title/text` فارسی + `title_en/text_en` + `video_url` |
| `questions` | نگاشت پرسش‌های متنوع (فارسی و انگلیسی) به ورودی‌های دیتاست |
| `synonyms` | مترادف‌های فارسی برای بسط پرس‌وجو |
| `settings` | کلید-مقدار: برندینگ `whitelabel_*`، اتصال `ai_*`، سوییچ‌ها، تم فعال |
| `chat_logs` | همه‌ی تعامل‌ها با اطمینان، توکن و هزینه |
| `admins`, `admin_sessions` | احراز هویت پنل |
| `media` | متادیتای فایل‌های آپلودشده |

اسکیما در `app/db/connection.py` ساخته می‌شود (idempotent، بدون سیستم مایگریشن — ستون‌های
جدید با `ensure_dataset_columns()` به نصب‌های موجود اضافه می‌شوند). مسیر فایل DB با
`DB_PATH` env قابل جابه‌جایی است (برای volume داکر).

## ۸. تست و استقرار

- **تست:** pytest — ۴۶+ تست واحد/یکپارچه (خط لوله‌ی TF-IDF، نرمال‌سازی فارسی، امنیت،
  seed دوزبانه، قرارداد توکن‌های CSS) + تست‌های e2e مرورگری با Playwright در `tests/e2e/`.
- **CI:** GitHub Actions (`.github/workflows/ci.yml`) روی هر push/PR: کامپایل + کل suite.
- **استقرار:** `Dockerfile` + `docker-compose.yml` با volume جدا برای داده و مدیا و
  healthcheck روی `/api/health`؛ یا اجرای مستقیم `python main.py` / uvicorn.
- **پشتیبان‌گیری:** از پنل (تهیه، بازیابی، زمان‌بندی) — `backup_db.py`.

## ۹. نقشه‌راه فنی

1. جایگزینی بازیاب TF-IDF با **embedding محلی چندزبانه** (اجرا روی همان سرور، بدون API
   بیرونی) پشت همان interface ی `search.py` — گام اصلی به‌سوی فناوری اختصاصی.
2. آموزش دسته‌بند نیت سبک روی داده‌ی پرسش‌های واقعی همان نصب (جایگزین دسته‌بندی LLM).
3. داشبورد مانیتورینگ زمان اجرا (نرخ پاسخ محلی/AI، تأخیر، خطاها) روی همان chat_logs.
4. مایگریشن اسکیمای نسخه‌دار در صورت رشد مدل داده.
