# بازدید هدفمند (Targeted Visit) — Feature Notes

تاریخ: ۲۰۲۶-۰۸-۱۶ · وضعیت: پیاده‌سازی‌شده، در انتظار بازبینی انسانی

پیشنهاد بخش‌های نمایشگاه بر اساس شغل، سمت و علاقه‌مندی‌ای که بازدیدکننده در
فرم «بازدید هوشمند» وارد می‌کند.

## قید اصلی: چه چیزی پیشنهاد نمی‌شود

**فهرست غرفه‌داران روی سایت رسمی منتشر نشده است.** بنابراین موتور فقط بین
۱۲ بخش و رویداد رسمیِ تأییدشده (همان‌ها که در `content/sources.json` مرجع
دارند) رتبه‌بندی می‌کند و هرگز نام شرکت یا شمارهٔ غرفه نمی‌سازد. هر پاسخ یک
`note` همراه دارد که همین را به زبان بازدیدکننده می‌گوید.

این تصمیم عمدی است: «شخصی‌سازی» با دادهٔ ساختگی، همان چیزی است که این پروژه
از ابتدا قرار بود نداشته باشد.

## معماری

| قطعه | مسیر |
|------|------|
| موتور رتبه‌بندی | `app/services/visit_plan.py` |
| API عمومی | `POST /api/visit-plan` (در `app/routers/otp.py` — ماژول registration) |
| پاسخ شخصی‌سازی‌شدهٔ چت | `app/routers/chat.py :: _targeted_visit_suffix` |
| مرحلهٔ پلن در مودال | `static/companion/registration.js :: renderPlanStep` |
| ورودی چت | `static/chat/core.js :: visitorProfile` |
| محتوای پایه | `app/default_content.py` → `inotex-targeted-visit` |
| تست‌ها | `tests/test_visit_plan.py` (۲۰ تست) |

## منطق تطبیق

۱. متن پروفایل (شغل + سمت + علاقه‌مندی) با `normalize_persian` نرمال می‌شود.
۲. برای هر بخش، تعداد کلیدواژه‌های **متمایز** یافت‌شده شمرده می‌شود:
   - کلیدواژهٔ چندکلمه‌ای → تطبیق زیررشته‌ای
   - توکن لاتین → فقط تطبیق کلمهٔ کامل (وگرنه «email» کلیدواژهٔ «ai» را
     فعال می‌کرد)
   - توکن فارسی ≥ ۴ حرف → تطبیق پیشوندی، تا «استارتاپی» به «استارتاپ» برسد
   کلیدواژه‌ها یک‌بار در زمان import نرمال و **یکتا** می‌شوند؛ پس «هوش‌مصنوعی»
   و «هوش مصنوعی» یک نتیجه‌اند نه دو.
۳. دو تطبیق = امتیاز کامل (۱.۰). تعداد تطبیق‌ها فقط تساوی‌ها را می‌شکند تا
   بخشی که صرفاً مترادف بیشتری فهرست کرده، بالاتر ننشیند.
۴. اگر هیچ تطبیق لفظی نبود، شباهت امبدینگ محلی به‌عنوان نجات‌دهنده — سقف ۰.۶،
   چون یک تطبیق معنایی هرگز نباید به قوّت کلمات خودِ بازدیدکننده جلوه کند.
۵. اگر باز هم چیزی نبود: `FALLBACK_IDS` (استیج + جشنوارهٔ پیشگامان) با امتیاز
   صفر و **بدون** دلیل ساختگی، و `matched: false`.

حداکثر ۴ بخش برگردانده می‌شود.

## حریم خصوصی

- در درخواست چت فقط سه فیلد توصیفی (`job`, `position`, `interests`) می‌رود؛
  نام و شمارهٔ موبایل هرگز همراه پیام‌های چت ارسال نمی‌شوند.
- اگر `challenge_id` تأییدشده ارسال شود، نسخهٔ ذخیره‌شده در سرور بر بدنهٔ
  درخواست اولویت دارد — مرورگر نمی‌تواند پروفایل را جعل کند.
- `profile_for` برای challenge تأییدنشده چیزی برنمی‌گرداند.

## نکات باز

- وقتی فهرست رسمی غرفه‌داران منتشر شد، همین ساختار می‌تواند به سطح غرفه برود؛
  تا آن زمان `note` باید سر جایش بماند.
- کلیدواژه‌ها دستی‌اند و از واژگان خود سایت رسمی گرفته شده‌اند؛ افزودن کلیدواژه
  نیاز به بازبینی دارد تا بخش‌ها با هم هم‌پوشانی بی‌مورد پیدا نکنند.
